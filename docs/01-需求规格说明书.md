**项目**：城市居住数据可视化与智能分析平台（二手房）

> 本文件描述系统的业务目标、功能边界、数据要求与验收标准，作为后续分工、设计、开发与测试的依据。

## 1 引言

### 1.1 编写目的

明确平台要解决的问题、要交付的能力与可验证的标准，使六名成员对"做什么、做到什么程度"形成一致理解，并为后续的模块划分提供依据。

### 1.2 项目背景

现有开源项目以医疗问诊数据为对象，已具备数据采集、数据库存储、可视化大屏、文本分类与对话功能，但业务字段与页面文案固定在医疗场景。本项目以二手房在售房源数据替换原数据，保留原有的字段结构与图表骨架，重点补充数据实时更新、智能问答与任务编排能力。

### 1.3 术语与缩写

| 术语 | 说明 |
|---|---|
| 槽位 | `cases` 表中的 13 个业务字段，字段名固定，语义由领域配置定义 |
| 领域配置 | `backend/domain/profiles/*.yaml`，描述字段标签、图表标题、分箱规则 |
| 适配器 | 把某类数据源转换为 13 个槽位的实现类 |
| 版本快照 | 一次数据变更对应的整表副本，用于追溯与回滚 |
| Agent | 能理解用户意图、调用工具、组织结果的对话式智能体 |
| 工具 | Agent 可调用的后端能力，如查询、统计、预测、导出 |
| 降级 | 依赖不可用时回退到可用方案，如无模型时返回规则结果 |

## 2 项目概述

### 2.1 产品定位

面向课程演示与小型分析场景，提供"一屏看市场、一表查明细、一句话问数据、一步出报告"的能力。系统以二手房为主领域，通过领域配置保留切换到其他题材的可能。

### 2.2 建设目标

1. 数据可用：房源数据可采集、可导入、可去重、可追溯。
2. 展示可读：九个图表位与筛选条件对应居住业务语义，指标含义清晰。
3. 问答可信：对话中的数字来自后端工具返回，避免模型凭空生成。
4. 工程可扩：新增数据源只写适配器，新增领域只改配置文件。

### 2.3 成功标准

| 维度 | 指标 | 目标值 |
|---|---|---|
| 数据规模 | 演示数据条数 | 不少于 5000 条 |
| 数据覆盖 | 区域、户型、装修取值 | 各不少于 6、5、3 种 |
| 接口性能 | 大屏聚合接口 P95 | 不超过 1 秒 |
| 分类效果 | 测试集 F1 | 不低于 0.80 |
| 对话质量 | 标准问题集工具调用正确率 | 不低于 90% |
| 对话可信 | 回答数字与数据库一致率 | 100% |
| 交付完整 | 页面数量 | 不少于 9 个 |

### 2.4 用户角色

| 角色 | 特征 | 关注点 | 主要操作 |
|---|---|---|---|
| 浏览者 | 课程演示、快速了解市场 | 总体趋势、热门区域 | 查看大屏、使用筛选、询问助手 |
| 分析者 | 需要核对数据、整理材料 | 明细准确性、数据版本 | 查询明细、导入导出、生成报告 |
| 管理员 | 维护数据与配置 | 采集状态、领域配置 | 触发采集、查看日志、切换领域 |

### 2.5 运行环境

| 项 | 要求 |
|---|---|
| 服务端 | Python 3.10 及以上，Flask 3 |
| 数据库 | MySQL 8.0，字符集 utf8mb4 |
| 客户端 | Chrome 或 Edge 最新版，分辨率 1366×768 及以上 |
| 部署 | 单机部署，前后端分离，后端默认 5000 端口 |

### 2.6 约束与假设

1. 数据来源为公开页面与公开数据集，采集频率受站点规则限制。
2. 演示环境可能无外网，系统提供离线数据与本地生成两种模式。
3. 课程周期内以单城市数据为主，暂不实现多城市切换。
4. 系统不采集房源联系人电话等个人敏感信息。

## 3 业务分析

### 3.1 业务流程

1. 数据获取：按区域分页采集列表页，或导入离线文件。
2. 数据清洗：统一面积、总价、房龄的数值格式，剔除异常记录。
3. 数据入库：按详情链接去重后写入 `cases` 表。
4. 版本记录：每次批量写入生成一条版本记录与整表快照。
5. 数据展示：大屏读取聚合结果，明细页读取分页数据。
6. 智能问答：用户提问后，Agent 调用查询与统计工具，组织回答并附图表。
7. 报告输出：按模板生成统计报告，导出为 PDF 或 Word。

### 3.2 数据流转

```text
列表页 / CSV / 开放接口
        │
        ▼
   数据源适配器  ──►  字段清洗与去重  ──►  cases 表
                                          │
                              版本记录与快照
                                          │
        ┌─────────────────────────────────┼──────────────────────┐
        ▼                                 ▼                      ▼
   聚合服务（指标、图表）          明细服务（分页、筛选）     Agent 工具集
        │                                 │                      │
        ▼                                 ▼                      ▼
      大屏页面                        数据管理页              对话工作台
```

### 3.3 业务规则

| 编号 | 规则 | 说明 |
|---|---|---|
| BR-01 | 唯一性 | 详情链接相同的记录只保留一条 |
| BR-02 | 限速 | 同一站点连续请求间隔不少于 5 秒 |
| BR-03 | 数值合法 | 面积在 10 至 1000 平方米之间，总价在 10 至 10000 万元之间 |
| BR-04 | 时间格式 | 挂牌日期统一为 `MM.DD` |
| BR-05 | 领域语义 | 字段含义由领域配置决定，展示层不写死业务名称 |
| BR-06 | 只读优先 | Agent 默认只执行查询类工具，导出类操作需用户确认 |

### 4.2 关键用例说明

**UC-01 浏览大屏**

- 前置条件：服务已启动，数据源可用或存在缓存数据。
- 主流程：进入首页；系统返回关键指标与九组图表数据；页面渲染指标卡、图表与房源列表。
- 异常流程：数据源不可用时返回缓存数据，并在页面提示数据时间。
- 后置条件：页面展示的指标与数据库当前数据一致。

**UC-05 触发采集**

- 前置条件：管理员已登录后台，数据源处于启用状态。
- 主流程：选择数据源与页数；系统按区域逐页采集；清洗去重后入库；记录版本与增量条数；页面状态由采集中变为成功。
- 异常流程：站点返回验证码或超时，记录失败原因，状态置为异常，已入库数据保留。
- 后置条件：版本列表新增一条记录，大屏数据随之更新。

**UC-10 对话问答**

- 前置条件：对话服务可用，数据已完成加载。
- 主流程：用户输入问题；系统识别意图；调用统计或查询工具；组织回答；以文字加图表卡片的形式返回。
- 异常流程：意图无法识别时提出一次澄清；工具执行失败时说明原因并给出可用操作建议。
- 后置条件：会话历史保留本轮问答，可继续追问。

**UC-11 Agent 多步任务**

- 前置条件：同上。
- 主流程：用户提出复合请求，例如"找出朝阳区近三个月总价 500 万以内的两居，按小区统计数量并画出柱状图"；Agent 拆解为筛选、聚合、出图三步；依次调用工具；汇总结果并返回图表。
- 异常流程：参数缺省时使用默认值并在回答中声明；任一步失败时返回已完成部分。
- 后置条件：会话中保留工具调用轨迹，便于核对。

## 6 AI 对话与 Agent 需求

本章为独立模块，由占竞负责实现，其余模块通过工具接口与其衔接。

### 6.1 模块定位

对话模块承担两类任务：一是基于数据的问答，二是把多步操作交给 Agent 编排。前者强调回答准确，后者强调一次表达就能完成筛选、统计与出图。

### 6.2 能力清单

| 能力 | 说明 | 对应需求 |
|---|---|---|
| 意图识别 | 区分查数、问概念、要图表、要报告、闲聊五类意图 | FR-18 |
| 参数补全 | 从对话中提取区域、户型、价格区间、时间范围 | FR-18 |
| 工具编排 | 单轮调用一个或多个工具，按依赖顺序执行 | FR-18 |
| 结果组织 | 将工具结果整理为结论、表格与图表卡片 | FR-19 |
| 澄清追问 | 关键参数缺失时提出一次澄清 | FR-17 |
| 上下文延续 | 支持"那海淀区呢""再按户型拆一下"等追问 | FR-20 |
| 安全兜底 | 无工具结果时不编造数字 | FR-21 |

### 6.3 工具契约

| 工具名 | 用途 | 入参 | 返回 | 约束 |
|---|---|---|---|---|
| query_cases | 按条件查询房源 | 区域、户型、装修、价格区间、面积区间、上限条数 | 明细列表与总数 | 只读，上限 50 条 |
| aggregate_stats | 分组聚合 | 指标（数量、均价、面积）、维度（区域、户型、装修、月份）、筛选条件 | 分组结果 | 只读 |
| price_distribution | 价格分箱 | 筛选条件、分箱区间 | 各区间计数 | 只读 |
| find_similar | 相似房源 | 描述文本、返回条数 | 房源列表与相似度 | 只读，上限 10 条 |
| predict_category | 分类预测 | 描述文本 | 标签与置信度 | 依赖模型服务 |
| list_meta | 取维度取值 | 维度名称 | 取值列表 | 结果缓存 10 分钟 |
| render_chart | 生成图表配置 | 图表类型、数据来源 | 图表配置对象 | 仅用于展示 |
| draft_report | 生成报告草稿 | 模板、筛选条件 | 报告块结构 | 仅生成预览 |
| export_report | 导出报告 | 模板、筛选条件、格式 | 文件地址 | 需二次确认 |

### 6.4 会话流程

1. 接收问题，识别意图与实体。
2. 检查参数完整性，缺失时澄清一次。
3. 选择工具并校验参数，非法参数转换为提示。
4. 依次执行工具，记录调用轨迹与耗时。
5. 组织回答：结论在前，数据在中，图表在后。
6. 保存会话记录与工具轨迹。

### 6.5 上下文与记忆

- 会话级：最近六轮对话原文，超出后压缩为摘要。
- 数据级：本轮使用的数据快照时间随回答返回，便于核对。
- 偏好级：记录用户常用区域与户型，作为默认筛选条件。

### 6.6 安全与边界

| 编号 | 规则 | 说明 |
|---|---|---|
| SR-01 | 数字可追溯 | 回答中的数字必须来自工具返回，禁止模型自行推算 |
| SR-02 | 写操作确认 | 导出、保存等操作在执行前向用户确认 |
| SR-03 | 敏感信息 | 不返回房源联系人电话等信息 |
| SR-04 | 越权请求 | 与数据无关的请求礼貌拒绝并说明能力范围 |
| SR-05 | 失败说明 | 工具超时或异常时说明原因，不返回猜测结果 |

### 6.7 性能与降级

| 项 | 要求 |
|---|---|
| 首字延迟 | 不超过 2 秒 |
| 单工具耗时 | 不超过 3 秒，超时重试一次 |
| 整轮超时 | 不超过 15 秒 |
| 降级策略 | 模型不可用时返回规则统计结果，并标注"未使用模型" |

### 6.8 验收标准

1. 标准问题集包含 20 个问题，覆盖查询、统计、图表、报告四类。
2. 工具调用正确率不低于 90%。
3. 回答中的数字与数据库查询结果一致率 100%。
4. 无工具可用时能够给出明确说明，不出现编造数字。
5. 连续追问三轮后，上下文仍然有效。

| content | 标题与描述 | 文本 | 满五唯一 近地铁 | 非空 |
| docName | 经纪人 | 文本 | 王×× | 可空 |
| docHospital | 小区 | 文本 | ××花园 | 可空 |

### 7.3 数据量与更新

| 项 | 要求 |
|---|---|

### 7.4 数据质量规则

## 12 风险与待确认事项

### 12.1 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 站点反爬升级 | 采集失败 | 降低频率、切换站点、使用公开数据集 |
| 演示环境无外网 | 无法实时采集 | 提供离线快照与本地生成模式 |
| 模型精度不足 | 分类结果不可用 | 扩充样本、调整标签粒度、保留规则兜底 |
| Agent 生成的数字失真 | 回答不可信 | 数字全部来自工具，禁止模型推算 |
| 文档与实现脱节 | 验收扣分 | 需求变更同步更新文档与测试用例 |

### 12.2 待确认事项

| 编号 | 事项 | 备选方案 | 影响 |
|---|---|---|---|
| Q-01 | 分类标签用户型还是价格档位 | 户型（5 至 6 类）或价格档（3 类） | 影响数据集与评估指标 |
| Q-02 | Agent 是否包含写入类工具 | 仅查询与导出，或增加保存筛选条件 | 影响安全边界与工作量 |
| Q-03 | 相似检索使用向量库还是内存计算 | 内存余弦计算或引入向量库 | 影响依赖与部署复杂度 |
| Q-04 | 数据源以链家为主还是以开放数据为主 | 链家为主、开放数据兜底 | 影响采集模块设计 |
| Q-05 | 报告导出是否同时支持 PDF 与 Word | 两者都做或先做 PDF | 影响模板渲染方式 |
