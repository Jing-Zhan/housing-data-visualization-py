# 需求规格说明书（草稿）

> 状态：编写中。第 3、6 章已给出初稿，其余章节按分工补充。
> 对应课程要求：需求分析与软件设计（UML 建模）。

## 1. 引言

### 1.1 编写目的

本文档描述城市居住数据可视化与智能分析平台的业务需求、功能需求与约束条件，作为设计、开发与验收的依据。

### 1.2 项目范围

系统以二手房在售房源数据为对象，提供数据采集、入库、可视化展示、文本分类预测、大模型对话与报告导出功能。
系统沿用原医疗数据可视化项目的 13 个字段槽位与页面结构，通过领域配置切换题材。

### 1.3 术语

| 术语 | 说明 |
|---|---|
| 槽位 | 数据库 `cases` 表中的 13 个业务字段，语义由领域配置定义 |
| 领域配置 | `backend/domain/profiles/*.yaml`，描述字段标签、图表标题与分箱规则 |
| 适配器 | 把不同数据源转换为 13 个槽位的实现类 |
| 版本快照 | `data_versions` 与 `cases_snapshot` 记录的一次数据状态 |

### 1.4 参考资料

- 课程作业要求（六项）
- 原医疗数据可视化系统源码（`backend/legacy/`）
- 链家二手房站点结构与公开数据集说明

## 2. 总体描述

### 2.1 产品定位

面向课程演示与城市居住数据分析场景，提供"一屏看全市场、一键查明细、一句话问数据"的能力。

### 2.2 用户角色

| 角色 | 关注点 | 主要操作 |
|---|---|---|
| 普通用户 | 市场概况 | 浏览大屏、筛选区域与户型、查看房源明细 |
| 分析人员 | 数据质量与趋势 | 导入导出数据、查看采集状态与版本记录 |
| 系统管理员 | 运行状态 | 启停数据源、切换领域配置、触发采集 |

### 2.3 运行环境

- 服务端：Python 3.10+、Flask 3、MySQL 8
- 客户端：Chrome / Edge 最新版
- 部署：单机部署，前后端分离

### 2.4 约束与假设

- 数据来源于公开列表页，采集频率受站点规则限制。
- 演示环境可能无外网，需要提供离线快照样例。
- 房源文本字段需从详情页补充，列表页不含描述。

## 3. 功能需求

| 编号 | 名称 | 描述 | 优先级 |
|---|---|---|---|
| FR-01 | 数据采集 | 按区域分页采集列表页公开字段，单页间隔不少于 5 秒，按 `detailUrl` 去重 | 高 |
| FR-02 | 数据导入 | 支持 CSV / Excel 导入，列名与 13 个槽位一致，返回解析条数与预览 | 高 |
| FR-03 | 数据导出 | 按当前领域导出 CSV，编码 UTF-8 with BOM | 中 |
| FR-04 | 大屏总览 | 返回关键指标与 6 组图表数据，标题取自领域配置 | 高 |
| FR-05 | 明细查询 | 按分页返回房源明细，支持按区域、户型筛选 | 高 |
| FR-06 | 实时更新 | 定时增量采集，写入新数据并生成版本快照，向前端推送更新事件 | 高 |
| FR-07 | 文本分类 | 输入房源标题与描述，输出户型或价格档位及置信度 | 中 |
| FR-08 | 相似检索 | 输入文本，返回语义相近的历史房源 | 中 |
| FR-09 | 智能对话 | 通过 WebSocket 与大模型对话，回答中引用当前数据统计 | 高 |
| FR-10 | 报告导出 | 按模板生成统计报告，支持 PDF 与 Word | 中 |
| FR-11 | 领域切换 | 读取领域配置，切换后前端标签与图表标题随之变化 | 中 |
| FR-12 | 数据源监控 | 展示各数据源状态、上次采集时间与增量条数 | 低 |

## 4. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 大屏接口在 3000 条数据规模下响应时间不超过 1 秒 |
| NFR-02 | 可用性 | 数据源不可用时返回缓存数据并提示状态，页面不出现空白 |
| NFR-03 | 可维护性 | 新增数据源只需实现适配器接口，不修改业务层代码 |
| NFR-04 | 安全性 | 密钥通过环境变量注入，仓库不保存 `.env` |
| NFR-05 | 兼容性 | 前端支持 1920×1080 与 1366×768 两种分辨率 |

## 5. 数据需求

### 5.1 数据实体

`cases` 事实表承载房源数据，字段语义见 README 的"13 个字段槽位"。

### 5.2 数据量

演示数据不少于 3000 条，覆盖不少于 6 个区域、5 种户型。

### 5.3 数据质量

- `detailUrl` 唯一，用于去重
- `height`、`weight` 为正数，异常值置空
- `time` 统一为 `MM.DD` 格式

## 6. 界面需求

| 页面 | 路由 | 主要内容 |
|---|---|---|
| 大屏总览 | `/` | 关键指标、6 组图表、房源列表、筛选条件 |
| 数据管理 | `/tableData` | 明细表格、导入导出、数据源状态、版本记录 |
| 在线预测 | `/pred` | 文本输入、分类结果、相似房源 |
| 报告生成 | `/report` | 模板选择、参数配置、预览与导出 |
| 智能对话 | `/ai-chat` | 会话窗口、历史记录 |

## 7. 接口需求

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/health` | GET | 健康检查，返回领域与数据源 |
| `/api/dashboard/overview` | GET | 大屏聚合数据 |
| `/api/data/cases` | GET | 明细分页 |
| `/api/data/import` | POST | 文件导入解析 |
| `/api/data/export` | GET | 导出 CSV |
| `/api/domain/profile` | GET | 领域配置 |
| `/api/ai/predict` | POST | 文本分类（待接入） |
| `/ws/chat` | WebSocket | 对话推送 |
