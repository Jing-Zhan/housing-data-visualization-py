## 二、必须修改

### 1. 回滚到不存在的版本会清空整张表

**位置**：`backend/repo/case_repo.py` 的 `restore_version()`

**现象**：方法先执行 `DELETE FROM cases`，再从快照插入。传入的版本号不存在时，删除已经执行、插入是 0 行，
整张表被清空，而且没有抛异常，还会再写一条 `restore` 版本记录。

**复现**：自检脚本第 9 项，回滚前 7 条，执行 `restore_version(999999)`，回滚后 0 条、无异常。

**影响**：版本号传错即丢数据。接口暴露后，前端点错一次就会清库。

**修改**：删除之前先确认版本存在且快照非空，不存在直接抛错，由接口层转成 404。

```python
    def restore_version(self, version_id: int, operator: str = "system") -> int:
        cols = ", ".join(SLOTS)
        conn = self._connect()
        try:
            with conn.cursor() as cursor:
                cursor.execute(
                    "SELECT COUNT(*) AS n FROM cases_snapshot WHERE version_id=%s",
                    (version_id,),
                )
                if cursor.fetchone()["n"] == 0:
                    raise ValueError(f"版本 {version_id} 不存在或快照为空")

                cursor.execute("DELETE FROM cases")
                cursor.execute(
                    f"INSERT INTO cases (id, {cols}) "
                    f"SELECT case_id, {cols} FROM cases_snapshot WHERE version_id = %s",
                    (version_id,),
                )
                restored = cursor.rowcount
                new_version_id = self._insert_version(
                    cursor, "restore", f"从版本 {version_id} 回滚", operator, delta=0
                )
                self._snapshot(cursor, new_version_id)
            conn.commit()
        except Exception:
            conn.rollback()
            raise
        finally:
            conn.close()
        return restored
```

**验收**：`restore_version(999999)` 抛 `ValueError`，表内条数不变。

### 2. 补版本列表与回滚接口

**现状**：仓库层已经有 `list_versions()` 和 `restore_version()`，但 `blueprints/data.py` 没有暴露，
请求 `/api/data/versions` 返回 404。数据管理页无法展示版本记录，也无法触发回滚。

**需求依据**：FR-07 的验收点是“版本列表可查到对应记录”，FR-08 是“回滚后总数与快照一致”。

**建议新增两个路由**：

```python
@bp.get("/versions")
def list_versions():
    """版本列表，按时间倒序。"""
    repo = CaseRepository(current_app.config["DB_CONFIG"])
    if not repo.ping():
        return jsonify({"code": 503, "message": "数据库不可用", "data": None}), 503
    limit = min(int(request.args.get("limit", 20)), 100)
    items = repo.list_versions(limit=limit)
    for item in items:
        item["created_at"] = str(item["created_at"])
    return jsonify(
        {"code": 200, "message": "success", "data": {"total": len(items), "items": items}}
    )


@bp.post("/versions/<int:version_id>/restore")
def restore_version(version_id):
    """按版本回滚数据。"""
    repo = CaseRepository(current_app.config["DB_CONFIG"])
    try:
        restored = repo.restore_version(version_id)
    except ValueError as exc:
        return jsonify({"code": 404, "message": str(exc), "data": None}), 404
    except Exception as exc:  # noqa: BLE001
        return jsonify({"code": 500, "message": f"回滚失败：{exc}", "data": None}), 500
    return jsonify(
        {"code": 200, "message": "success", "data": {"versionId": version_id, "restored": restored}}
    )
```

**验收**：

1. `GET /api/data/versions` 能查到刚导入产生的版本，字段含 `id`、`action`、`delta_records`、`created_at`；
2. 导入两次得到两个版本号，回滚到第一个，`cases` 条数回到第一次导入后的数量；
3. 回滚到 `999999` 返回 404，条数不变。

## 三、建议修改

### 3. `INSERT IGNORE` 会把非重复错误也算成“跳过”

现在 `skipped = len(payload) - inserted`。`INSERT IGNORE` 除了唯一键冲突，还会吞掉字段超长、类型不匹配等错误，
这些行会被算进 `skipped`，看起来像“重复”，排查时容易误判。

建议改成 `INSERT ... ON DUPLICATE KEY UPDATE id = id`，或在插入前先查一遍已存在的 `detailUrl`，
让 `skipped` 只统计真正重复的行。

### 4. 校验范围与需求不一致

`RANGE_SLOTS` 现在写的是面积 1~1000 ㎡、总价 1~100000 万；
需求 7.1 写的是面积 10~1000 ㎡、总价 10~10000 万。两边选一套，代码与文档保持一致。

### 5. 脚本导入没有版本记录

`scripts/import_csv.py` 还在调用 `insert_many`，导完不留版本记录。改成 `insert_with_version`，
脚本导入也能在版本列表里查到。返回值从整数变成了 `InsertResult`，打印语句同步调整：

```python
result = repo.insert_with_version(rows, action="import", description=f"脚本导入 {args.file}")
print(f"写入完成：新增 {result.inserted} 条，跳过重复 {result.skipped} 条，"
      f"异常 {result.invalid} 条，当前总数 {repo.count()} 条")
```

### 6. 调度器是全局单例

`start_scheduler` 用模块级 `_scheduler` 保存实例，应用工厂被多次调用时会拿到第一次的调度器，
测试之间会互相影响。建议补一个 `stop_scheduler()`，或在函数里判断实例绑定的 app 是否一致。

### 7. 数据库异常没有兜底

`/api/data/health` 和 `/api/data/sources/status` 直接调用仓储，数据库断开时会抛异常，
接口返回 500 并打一长串堆栈。建议用 `try/except` 包住，返回 503 与简短说明。
